## What to build

Expose the core Document/Layer model and the layer-aware DocumentHistory
through the UniFFI crate so the Swift shell can create, edit, composite, and
undo layered documents. This is the **expand** step of an expand–contract
sequence: the existing `ApplePixelCanvas` / `AppleHistoryManager` bindings and
everything consuming them stay untouched; the editor migrates onto the new
objects in the follow-up state-redesign issue, which also performs the
contract.

Scope is defined by what that editor swap consumes — no speculative surface:

- **A document object** wrapping the core `Document` (interior-mutability
  pattern per the existing UniFFI ADR), constructible as a width × height
  single-pixel-layer document.
- **Reads**: document dimensions; the layer stack in stack order as
  shell-facing records (id, name, visible, kind tag); the active layer id;
  the monotonic next-layer-number counter.
- **Structure ops**: add layer (above active, becomes active — core
  semantics), remove layer (sole-layer removal surfaces the core error),
  set visibility, set active, reorder.
- **Drawing ops** the stroke engine needs, targeting the active layer's
  cel: apply tool, flood fill, get/set pixel, clear.
- **Resize** with anchor (core `Document::resize`).
- **Composite**: the on-screen composite buffer for the Metal render path,
  and the export-oriented composite + PNG encoding for the export path.
- **A document history object** wrapping core `DocumentHistory`:
  begin-edit / end-edit (commit only when the document actually changed),
  can-undo / can-redo, undo / redo returning the restored document, clear.

Layer ids cross the FFI boundary as strings (UniFFI has no UUID type; the
web bindings already use string ids).

## Acceptance criteria

- Swift binding tests (Swift Testing, following the existing
  `CanvasBindingsTests` pattern) prove through the generated bindings:
  - a new document reports the requested dimensions and a single visible
    pixel layer that is active;
  - a tool op draws into the active layer and the composite reflects it;
  - add / remove / set-visibility / set-active / reorder round-trip,
    including the sole-layer-removal error and add-layer's above-active +
    becomes-active placement;
  - history: a no-change edit records no entry; a real edit undoes and
    redoes correctly across pixel edits, layer-structure changes, and a
    resize (dimensions restore with the document).
- `cargo test` passes; UniFFI regeneration produces Swift that compiles in
  the Xcode project.
- Existing bindings, shell code, and shell behavior are untouched.

### Key Decisions

- Layer ids cross the boundary as **lowercase** UUID strings (`Uuid::to_string()` emits lowercase hex); Swift's uppercase `UUID().uuidString` is accepted on input and normalized on read.
- Layer kind crosses as the core `LayerKindTag` enum rather than the web binding's `"pixel"`/`"reference"` strings — UniFFI supports enums directly, giving Swift a typed contract.
- `flood_fill` mirrors `ApplePixelCanvas`'s contract: negative coordinates short-circuit to `false`.
- `encode_export_png` composes `composite_for_export()` + `PixelCanvas::from_pixels().encode_png()` — no new core export surface.
- `AppleDocumentHistory.undo/redo` return the restored document as a **new** `AppleDocument` object; the shell replaces its reference (matches core's value-snapshot semantics).
- `reorder_layer`'s index and `new(max_snapshots:)` use `u64` (UniFFI has no `usize`), following the existing `AppleHistoryManager` precedent.
