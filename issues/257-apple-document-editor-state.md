## What to build

The Swift-side state-architecture redesign the RFC names as Phase 3's core:
the editor's backing model switches from a single pixel canvas plus
canvas-snapshot history to a Document (holding one pixel layer, for now)
plus whole-document DocumentHistory. Every editor behavior re-routes through
the document; **the user sees no difference** — regression parity on a
single-layer document is the demo.

- **Strokes draw into the active layer.** All tools (pencil, eraser, line,
  rect, ellipse, fill, eyedropper, move) run against the document through
  the stroke-session seam, which stays deliberately narrow — sessions see a
  drawing surface, not the whole editor.
- **Metal renders the document composite.** Grid, hover highlight, and other
  overlays are unchanged.
- **Undo/redo restores whole-document snapshots.** Edit Baseline semantics
  are preserved: the entry commits only when the edit changed the document;
  no-op strokes leave history (including the redo future) untouched.
- **Clear, PNG export, hover bounds, and viewport clamping** read document
  dimensions.
- **Canvas resize becomes an undoable edit** (web parity — whole-document
  snapshots make cross-dimension restore representable), replacing today's
  clear-history-on-resize workaround. Content anchoring stays as it behaves
  today; the web's anchor selector UI is out of scope.
- **Eyedropper sampling encodes the web rule** — sample what the user sees
  (the composite). Indistinguishable from sampling the sole layer today, but
  the seam should carry the rule so multi-layer sampling needs no rework.
- **Contract step**: the editor's canvas-snapshot history path is removed;
  no editor code consumes `AppleHistoryManager` afterwards.

This issue adds no layer UI — the panel arrives in the follow-up issues.

## Acceptance criteria

- All existing editor behaviors regress clean: every tool, pixel-perfect
  filtering, Shift/latch constrain, undo/redo (including no-op strokes),
  clear, canvas resize, PNG export, zoom/pan/fit, pencil hover preview, and
  the pencil palm-rejection routing. Existing Swift Testing suites and
  docked snapshot tests stay green, migrated where they touched the old
  canvas-backed host.
- Canvas resize is undoable and redoable, restoring both pixels and
  dimensions (new behavior, web parity).
- The render path draws the composite: a layer whose `visible` flag is
  cleared disappears from the rendered output (pinned by tests even though
  no UI toggles it yet).
- No editor-path references to the canvas-snapshot history remain.
- macOS and iPadOS targets build clean.

### Key Decisions

- First layer follows the web naming convention ("Layer 1"); ids cross the FFI boundary as lowercase UUID strings (256 convention).
- Resize keeps today's top-left content anchoring (the web's anchor selector UI stays out of scope) and commits through the Edit Baseline — a rejected resize resolves as a no-op edit and records nothing.
- Eyedropper and loupe sample the **composite** — the seam carries the "sample what the user sees" rule, so multi-layer sampling needs no rework.
- The session seam is enforced by type: `StrokeSessionHost` exposes `any DrawingSurface`, not the whole `AppleDocument` (review follow-up on the "sessions see a drawing surface" spec line).
- Contract scope widened deliberately (user decision): the `AppleHistoryManager` binding and its binding tests were deleted, not just editor consumption; `ApplePixelCanvas` survives for the render benchmark.
- `PixelGridRenderer` is no longer `final` so the render-path test can spy on the canvas-texture upload seam (user-chosen test seam).

### Notes

- Undo/redo adopt a **new** document object (core value-snapshot semantics) — anything holding the old reference re-reads through `EditorState`.
- Platform nuance: the web eyedropper samples the active layer (`try_get_pixel`, Reference-aware) while Apple samples the composite; identical on a single-layer document, worth revisiting when the Apple layer panel (258+) lands.
- Verified: `cargo test --workspace` 568 green; full Apple suite 261 tests / 55 suites on the pinned simulator; macOS target builds clean.
- `apple/generated` was regenerated manually after each binding change — the mtime-based staleness guard remains a backlog item.
