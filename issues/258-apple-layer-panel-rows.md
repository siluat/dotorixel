## What to build

The first visible layer UI: a Layers section in the right panel (docked
layout as reference, SwiftUI-native controls per the RFC's hybrid design
decision) that lists the document's layers and lets the user pick the
drawing target and toggle visibility.

- One row per layer in **panel order** (top of stack at the top of the
  panel), each showing the layer name and a visibility eye.
- **Tapping a row makes that layer active** — subsequent strokes land
  there. The active row is visually distinct. Set-active is not undoable
  and no-ops while a stroke is drawing (web parity).
- **The eye toggles visibility**; the Metal composite updates immediately.
  A real change records one undo entry; a no-op change records nothing
  (web parity). A hidden layer stays selectable and drawable.
- Touch targets ≥ 44 pt on touch tiers; labels localized via the String
  Catalog (en/ko/ja); the section behaves across the layout tiers.

Add/remove and reorder controls arrive in the follow-up issues — until
then multi-layer behavior is pinned by tests on programmatically-built
documents, while single-layer visibility toggling is already demoable live.

## Acceptance criteria

- The panel lists layers top-to-bottom in panel order with name and
  visibility state; the active row is visually distinct.
- Tapping a row switches the drawing target: on a multi-layer document
  (built programmatically in tests), a stroke after switching lands on the
  tapped layer and nowhere else.
- Set-active records no history entry, no-ops on the already-active row,
  and no-ops while a stroke is drawing (web parity).
- The eye toggle removes/restores the layer in the rendered composite
  immediately; one undo entry per real change, none for a no-op (web
  parity); undo restores the previous visibility.
- A hidden layer can still be made active and drawn on (web parity).
- Row touch targets are ≥ 44 pt on touch tiers; all new labels live in the
  String Catalog with en/ko/ja entries.
- Docked snapshot tests cover the Layers section at the relevant tiers.
- macOS and iPadOS targets build clean.
