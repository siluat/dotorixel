## What to build

Layer creation and deletion from the Layers panel — the point where the
multi-layer workflow becomes fully live on the Apple shell.

- **Add-layer control** in the Layers section: creates a transparent pixel
  layer directly above the active layer and makes it active (core
  semantics), auto-named with the localized default layer name and the
  document's monotonic layer counter (web parity — the counter never
  decrements, so names stay unique across the document's lifetime).
- **Remove control** per row, mirroring the web affordance: removes the
  layer; when the removed layer was active, the active pointer moves to an
  adjacent layer (delegated to the core). The **sole-layer guard** prevents
  removing the last layer and surfaces as a disabled affordance; the guard
  branch records no history entry. Remove no-ops while a stroke is drawing
  (web parity — a live stroke's target must not vanish mid-stroke).
- Both real operations are **undoable**: undoing an add restores the
  pre-add document; undoing a remove restores the removed layer with its
  pixels, stack position, and active state.
- Touch targets ≥ 44 pt; labels in the String Catalog (en/ko/ja).

## Acceptance criteria

- The add control inserts a transparent layer above the active layer, makes
  it active, and names it with the localized default name and the next
  counter value; the panel and composite update immediately.
- The remove control deletes the row's layer; removing the active layer
  moves the active pointer to an adjacent layer; the composite drops the
  removed layer's pixels immediately.
- Removing the last remaining layer is impossible and the affordance reads
  as disabled; no history entry is recorded on that branch.
- Remove no-ops while a stroke is drawing (web parity).
- Add and remove each record exactly one undo entry; undo/redo restores
  layer structure, pixels, and the active pointer.
- End-to-end demo passes on simulator: add a second layer, draw on both,
  hide one, remove one, undo the removal — the full layer workflow works
  through UI alone.
- Touch targets ≥ 44 pt on touch tiers; new labels in the String Catalog
  with en/ko/ja entries; docked snapshot tests updated where visuals
  changed.
- macOS and iPadOS targets build clean.

### Key Decisions

- **Mid-stroke seal extended to `addLayer`** (the issue mandated it only for remove): the core's `add_layer` activates the new layer, so admitting it mid-stroke would switch the stroke's target *and* replace the pending Edit Baseline — same rationale as 258's eye-toggle seal.
- **First layer name stays hardcoded "Layer 1"** — exact web parity: the web hardcodes it at document creation and localizes only added layers.
- **`canRemoveLayer` reads `canvasVersion`** for @Observable registration, following 258's facade pattern.
