## What to build

Reordering layers from the Layers panel, changing the composite stacking
order.

- Rows can be moved to a new position with a **SwiftUI-native reorder
  affordance** — the exact idiom (List reorder, drag handle, …) is an
  implementation decision per the RFC's hybrid design principle; the web
  reference is drag-based.
- **Panel order ↔ stack order translation**: top of panel = top of stack;
  the composite stacking updates immediately on drop.
- Dropping a layer at its current position is a **no-op** — no history
  entry, no re-render (web parity). A real move records exactly one undo
  entry; undo restores the previous order.
- The reorder affordance meets the ≥ 44 pt touch guideline; any new labels
  go in the String Catalog (en/ko/ja).

## Acceptance criteria

- Moving a row to a new position changes the rendered composite stacking
  accordingly, pinned by tests covering the panel→stack index translation
  (top of panel = top of stack).
- A drop at the layer's current position records no history entry; a real
  move records exactly one; undo restores the previous order and the
  previous rendered output.
- Reordering works with the active layer anywhere in the stack and never
  changes which layer is active.
- The affordance is usable by touch (≥ 44 pt) and by pointer on macOS; new
  labels (if any) live in the String Catalog with en/ko/ja entries.
- Docked snapshot tests updated where visuals changed.
- macOS and iPadOS targets build clean.
