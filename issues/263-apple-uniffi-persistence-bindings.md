## What to build

Expose the document serialization/hydration surface the persistence slice
needs through the UniFFI crate. **Expand only** — the existing bindings and
every consumer stay untouched (the pattern issue 256 established).

Scope is defined by what session persistence consumes — no speculative
surface:

- **Snapshot reads**: for each layer in stack order, the shell must be able
  to read everything the web persists per pixel layer — id, name, visibility,
  opacity, and the layer's pixel buffer (RGBA row-major). Today's bindings
  expose only metadata without opacity and the *active* layer's pixels;
  persistence needs every layer's.
- **Hydration**: a constructor wrapping the core's `Document::from_layers`
  that rebuilds a document from persisted parts — width, height, the layer
  records above, the active layer id, the monotonic next-layer-number
  counter, and the Timeline panel collapse flag. Core build errors (empty
  stack, duplicate id, dimension mismatch, unknown active layer) surface as
  thrown errors, not crashes.

Layer ids keep crossing the boundary as lowercase UUID strings, per the 256
convention. The core needs no new logic — `from_layers` already validates and
normalizes everything; this is binding work plus regeneration.

## Acceptance criteria

- Swift binding tests (following the existing `DocumentBindingsTests`
  pattern) prove through the generated bindings:
  - a multi-layer document with drawn pixels, a non-default active layer,
    an advanced layer counter, and a collapsed Timeline flag round-trips —
    snapshot reads → hydration constructor → a document whose composite,
    layer stack (ids, names, visibility, opacity, order), active layer id,
    next layer number, and collapse flag all match the original;
  - hydration surfaces the core build errors for an empty stack, a
    duplicate layer id, a layer whose pixel buffer doesn't match the
    document dimensions, and an unknown active layer id.
- `cargo test` passes; UniFFI regeneration produces Swift that compiles in
  the Xcode project.
- Existing bindings, shell code, and shell behavior are untouched.
