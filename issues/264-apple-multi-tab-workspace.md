## What to build

The multi-document workspace, on the state split issue 262 prepared: a user
can keep several documents open at once, each in its own tab, and move
between them freely. Web parity target is the `TabStrip` in the top area of
the editor, implemented with SwiftUI-native controls per the RFC's hybrid
design decision.

- **Tab strip**: one tab per open document showing its name, docked in the
  top area (web layout reference). The active tab is visually distinct.
- **Add**: a new-tab affordance creates a fresh default-size document named
  `Untitled N` — the lowest unused number, matching the web's naming rule —
  and makes it active.
- **Switch**: tapping a tab activates it. Each tab keeps its own document,
  undo/redo history, viewport (zoom/pan), canvas size, and Timeline panel
  collapse; the active tool, foreground/background colors, recent colors,
  and pixel-perfect flag are shared across tabs and carry over on switch.
  An in-flight stroke resolves before the switch — switching never corrupts
  the outgoing tab's history.
- **Close**: a per-tab close affordance. Since nothing is persisted yet,
  closing shows a simple destructive-confirmation alert ("discard this
  drawing?") — an honest interim that issue 266 replaces with the save
  dialog. Confirming removes the tab and activates the neighbor the way the
  web does; the last remaining tab cannot be closed.

i18n: new user-facing strings go through the String Catalog like the rest of
the shell.

## Acceptance criteria

- Adding tabs yields `Untitled 1`, `Untitled 2`, … reusing the lowest freed
  number, and each new tab becomes active.
- Drawing in tab A then switching to tab B shows B's own document and
  viewport; undo in B never affects A's history.
- Changing tool or colors in one tab is visible in every other tab.
- Closing a tab prompts for confirmation; confirming removes it and
  activates the adjacent tab (web index semantics); cancel leaves the
  workspace untouched. The close affordance is disabled or absent on the
  sole remaining tab.
- Workspace logic (naming, activation, close index math, shared-vs-per-tab
  state) is unit-tested; the tab strip appears in docked-view snapshots
  across the layout tiers.
- The canvas coordinator's originating-tab capture (`strokeTab` in
  `PixelCanvasView.Coordinator`, wired in 262 review) is regression-tested
  here, where `setActiveTab` first makes it exercisable. This does not
  contradict the Switch rule above — that rule is the policy layer
  (activation resolves an in-flight stroke first); the capture is the
  defense beneath it, for pointer events already in flight when the
  switch lands: those must still route to the originating tab, so a
  stroke begun on tab A ends or cancels on A, never on B.
