## What to build

Close and reopen the app without losing anything: the whole workspace comes
back exactly as it was left. This is the web's session-persistence behavior
(IndexedDB + `AutoSave`) delivered natively with SwiftData, on the document
model via the issue 263 bindings.

- **Schema**: per-document records covering the current Apple document model
  — dimensions, the pixel layer stack (id, name, visibility, opacity,
  pixels), active layer id, next layer number, Timeline panel collapse, a
  `saved` flag (written `false` for now; issue 266 gives it meaning), and
  created/updated timestamps — plus a singleton workspace record: tab order,
  active tab index, shared state (tool, foreground/background colors, recent
  colors, pixel-perfect), and each tab's viewport (zoom, pan, grid
  visibility). Reference layers, frames, and marquee are Phase 5–6 schema
  extensions, the way the web migrated v3→v7 — not persisted here.
- **Auto-save**: user mutations mark the workspace dirty (tracking which
  documents changed, so unchanged documents are not rewritten) and a
  debounced save writes in the background — the web debounces 3 s. Moving to
  the background or losing foreground (`scenePhase`) flushes any pending
  save immediately, the native analog of the web's `visibilitychange` /
  `beforeunload` flush. Restoring from a snapshot must not mark dirty (web
  parity: hydration is not a user mutation).
- **Restore**: on launch, rebuild the workspace from the store — every tab's
  document (via the hydration bindings), tab order, active tab, per-tab
  viewports, and shared state. No stored session, or a corrupt/unreadable
  one, falls back to a fresh single-tab session without crashing (web
  parity). Undo/redo history is session-transient and starts empty, as on
  the web.

## Acceptance criteria

- Draw in two tabs, change tool/colors, collapse the Timeline panel, adjust
  zoom/pan, then relaunch: tab order, active tab, every document
  (pixel-exact, layer structure and active layer included), per-tab
  viewports, grid visibility, tool, colors, recent colors, pixel-perfect,
  and the panel collapse all restore.
- Rapid consecutive edits coalesce into a debounced write; backgrounding
  the app flushes a pending save before the debounce elapses.
- Closing a tab removes it from the restored session.
- A corrupt or unreadable store yields a fresh blank session, not a crash;
  restored history starts empty.
- The persistence layer (serialization round-trip, dirty tracking, debounce
  and flush timing) is unit-tested with an in-memory store; a simulator
  relaunch pass verifies the end-to-end restore.
