## What to build

The Selection tool arrives on the Apple shell: pick it from the left
toolbar (shortcut `M`, web parity), drag on the canvas to define a Marquee,
click without dragging to deselect. The Marquee is persistent — it survives
tool switches — and visible as a marching-ants overlay.

- **Tool**: a new Selection tool case with toolbar button, icon, tooltip,
  and the `M` keyboard shortcut, following the existing tool plumbing
  (stroke-session species, tool routing, a11y labels).
- **Define**: a drag in any direction defines the Marquee via the core's
  drag normalization, clipped to the canvas; a drag preview shows the
  rectangle while defining. A click (no meaningful drag) clears the
  Marquee — both through the Edit Baseline so define/deselect are undoable
  and a no-op define pushes no history entry.
- **Overlay**: a marching-ants rectangle rendered above the Metal canvas,
  tracking zoom/pan so the ants hug the selected cells at every zoom
  level. Touch input routes through the existing originating-touch stroke
  routing (a second finger ends the define, pinch still zooms).
- Undo/redo restores the Marquee together with pixels — free via Document
  History snapshots; verify, don't rebuild.

Out of scope here: Shift-square constrain + latch and the StatusBar
readout (270), drawing-tool clipping (271), and everything Floating (272).
Drag-to-move inside the Marquee can be a no-op or plain redefine until 272
lands — pick whichever leaves 272 the cleanest seam.

## Acceptance criteria

- Selecting the tool (toolbar tap or `M`) and dragging defines a Marquee in
  any drag direction; the overlay ants match the selected pixel cells at
  multiple zoom levels and pan offsets.
- Click-without-drag deselects; the Marquee otherwise persists across tool
  switches and edits.
- Define and deselect are undoable; undo after a define restores the prior
  Marquee state.
- Defining with touch works on iPad (originating-touch binding; a pinch
  begun mid-define never paints a selection).
- Shell tests (stroke-session + view seams, following existing tool test
  patterns) cover define normalization, click-deselect, persistence across
  tool switch, and undo restoring the Marquee.

### Key Decisions

- **Inside-click never deselects** (web parity): a click inside the Marquee is
  the Floating Selection lifecycle's territory (272), so it no-ops — the
  cleanest seam for 272 to replace. Deselect fires only on an outside click.
- **`isConstrainable: false` until 270**: the web registry marks Selection
  constrainable, but Shift-square arrives with 270 — kept false so the latch
  badge never advertises a dead affordance (flip it in 270).
- **Engine dedup trusted over the web's anchor re-check**: the Apple
  `StrokeEngine` drops same-cell samples before the session, so the web
  session's `current == anchor` click guard is unreachable here and was
  removed ("trust the core" — the divergence is commented in the session).

### Notes

- Undo/redo restoring the Marquee is free via Document History
  whole-`Document` snapshots — verified by tests, no new plumbing.
- Touch routing needed no changes: sessions ride the existing
  originating-touch routing; the cancel test covers "a pinch begun mid-define
  never paints a selection".
- reduce-motion is applied at overlay appearance; a mid-display accessibility

- Verified: full Apple suite 415 tests / 83 suites green on the pinned
