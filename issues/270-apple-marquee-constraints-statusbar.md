## What to build

Selection-define ergonomics, matching the web:

- **Shift-square define**: holding Shift while defining a Marquee
  constrains it to a square, resolved through the same constraint path the
  shape tools use; toggling Shift mid-drag re-resolves the in-flight
  rectangle instantly.
- **Constrain latch**: the Selection tool joins the constrainable set —
  re-tapping the active Selection tool latches the square constraint
  keyboard-free, OR-combined with Shift, exactly like line/rect/ellipse
  today (this closes the "selection web-only" latch gap in
  platform-status).
- **StatusBar readout**: the status bar shows the active Marquee's
  dimensions and origin ("Marquee: W×H at (x, y)" full form), hidden when
  no Marquee exists, localized (en/ko/ja) via the String Catalog with the
  web's message-key vocabulary. It reflects committed state — it updates
  when a define/move commits, not per-frame during a drag.

## Acceptance criteria

- Shift held during define yields a square Marquee; releasing/pressing
  Shift mid-drag re-resolves the preview immediately.
- Re-tapping the active Selection tool toggles the latch; latched defines
  are square without a keyboard; Shift OR latch both constrain.
- The status bar shows the readout when a Marquee exists, in the current
  locale, and hides it when the Marquee clears; values match the actual
  region.
- Tests (constraint/latch contract tests and StatusBar view seam, following
  the existing `ConstrainStrokeTests` / view test patterns) cover the
  square resolve, latch toggle, and readout show/hide/values.
