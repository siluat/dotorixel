## What to build

Moving selected pixels: dragging from inside the Marquee lifts the region
into a Floating Selection (per the CONTEXT.md glossary — a transient buffer
plus translation offset, never a Layer, never persisted) that tracks the
drag; the Marquee ants follow the buffer. The Floating stays live after
release — commit happens on the web's explicit triggers.

- **Lift**: drag begins inside the Marquee → lift the region's pixels
  (267 bindings), clear the source to transparent, and preview the buffer
  at the drag offset. Rendering goes through the patch-composite read so
  the document is never mutated during preview. Drag outside the Marquee
  keeps defining a new Marquee (269 behavior).
- **Move**: release keeps the Floating active; subsequent drags inside it
  stack translation onto the same buffer.
- **Commit** (web-parity triggers): tool switch, pointer-down outside the
  Floating, Clear Canvas, active-layer removal, and — once those slices
  land — paste and canvas transforms. Commit composites the buffer at its
  final offset, clips at canvas edges, moves the Marquee to wrap the new
  location, and records **one undo entry** covering source-clear +
  destination-composite + Marquee move; undo restores all three.
- **Mid-gesture safety**: the Floating belongs to a tab — tab switches and
  the auto-save flush must not strand lifted pixels (resolve the Floating
  the way the web's policy does; consult the web's floating-selection
  orchestration before choosing the seam).
- Cancel (Escape) is slice 273; the action bar's Commit/Cancel buttons are
  slice 275.

## Acceptance criteria

- Drag from inside the Marquee lifts and moves the region; the source
  shows transparent immediately; ants and pixels track the drag at any
  zoom/pan.
- After release the Floating persists; another drag inside continues
  moving it; a pointer-down outside commits it.
- Commit produces exactly one undo entry; undo restores source pixels,
  destination pixels, and the Marquee position together; redo re-applies.
- A move ending at the original offset (net-zero) commits without pushing
  a history entry (no-op Edit discard).
- Off-canvas destinations clip at the canvas edge on commit; vacated areas
  stay transparent.
- Touch parity: the lift-drag works with a finger and Apple Pencil through
  the existing stroke routing; a pinch begun mid-move doesn't corrupt the
  Floating.
- Tests cover the lift/clear/preview lifecycle, commit triggers, the
  single-undo contract, net-zero discard, edge clipping, and
  tab-switch/auto-save resolution.

### Key Decisions

- Keep the Floating Selection as tab-owned transient state, never a Layer and never serialized.
- Clear the live source only for preview, render the destination through the patch-composite read, and project pre-lift pixels into persistence snapshots.
- Restore the exact pre-lift document before opening one Document History Edit; let the core classify net-zero commits and resolve every opened baseline even if application fails.
- Preserve a live Floating Selection across tab switches, while tool changes and conflicting document mutations commit it first.
- Treat Undo as cancellation while the Floating Selection is live and defer Redo until it is resolved.
