## What to build

The touch-first surface for selection operations — without it, iPad users
without a hardware keyboard can't cut/copy/paste, delete, transform, or
commit. A small action bar appears near the Marquee (web's placement
behavior) with two states:

- **Idle state** (Marquee, no Floating): Cut, Copy, Paste (enabled when
  the clipboard holds content), Delete, and the four **Marquee Transform**
  buttons — Flip Horizontal, Flip Vertical, Rotate Right, Rotate Left —
  each transforming only the Marquee region of the active layer (the tier
  the 267 bindings expose; each is one undoable step), plus Deselect.
- **Floating state**: Commit and Cancel, dispatching the same paths as
  pointer-commit and Escape.
- The bar tracks the Marquee/Floating position across zoom/pan, stays
  on-screen near canvas edges (web's clamping behavior), meets ≥44 pt
  touch targets, and exposes localized labels (en/ko/ja) with
  accessibility labels on every button.
- Hidden while a Reference Layer is active (Marquee preserved —
  future-proofing the reference track's 279 behavior; harmless before
  references exist).

This is the first UI surface for the Marquee Transform tier on Apple — the
transforms themselves come bound from 267; the bar is their trigger.

## Acceptance criteria

- The bar appears with a Marquee, switches button sets when a Floating
  starts, and disappears on deselect.
- Every button dispatches its existing operation (same undo semantics as
  the keyboard/pointer paths); the Marquee Transform buttons flip/rotate
  the region only, as single undo entries, and no-op sensibly when
  disabled.
- The bar follows the selection across zoom/pan and clamps to stay
  visible; all targets are ≥44 pt.
- Labels are localized and accessible (VoiceOver reads each action).
- View tests + snapshot tests (existing docked-view snapshot pattern)
  cover both states, dispatch wiring, and the enabled/disabled logic.

### Key Decisions

- Kept pixel transforms and no-op detection in the Rust core; the Apple shell only owns command routing, History boundaries, observation updates, and presentation.
- Modeled action sets, dispatch, and geometry behind explicit test seams while keeping the feature in one cohesive module.
- Preserved 44 pt targets on narrow viewports by horizontally scrolling the Idle action row instead of shrinking controls.
- Reused the command boundary's active-layer editability predicate so the bar automatically hides for Reference Layers without duplicating layer policy in SwiftUI.
