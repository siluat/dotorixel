## What to build

The Apple analog of the web's v5 migration (issue 134): the Marquee joins
the SwiftData session schema so a selection survives quit and relaunch.

- **Schema**: the per-document record gains the optional Marquee rectangle
  (absent = no selection). Existing stored sessions — records without the
  field — keep restoring exactly as before.
- **Save**: Marquee changes already flow through document edits, so the
  existing dirty-marking should cover them; verify define/deselect/move
  mark the document dirty and the debounced save writes the new field.
- **Restore**: hydration re-applies the stored Marquee to the rebuilt
  document; the selection overlay and status bar readout reflect it on
  first render. A stored rectangle that no longer fits the canvas (corrupt
  or hand-edited store) clips or drops at the boundary rather than
  crashing — boundary validation, per the store-read hardening precedent.
- A Floating Selection is never persisted (CONTEXT.md): a pending Floating
  resolves through the 272 flush policy before the snapshot is taken, so a
  mid-floating save can never lose lifted pixels.

## Acceptance criteria

- Define a Marquee, relaunch: the same selection is active (ants + readout
  correct). Deselect, relaunch: no selection.
- A pre-existing stored session (no Marquee field) restores unchanged.
- An out-of-bounds stored Marquee restores clipped or absent — never a
  crash, never a corrupted session.
- A save flushed while a Floating Selection is pending round-trips without
  losing the lifted pixels.
- Persistence tests (in-memory store, following the existing
  `SessionPersistenceTests` pattern) cover the round-trip, the absent
  field, boundary validation, and the pending-Floating flush.

### Key Decisions

- Store the Marquee as an optional composite value so pre-Marquee SwiftData
  stores use lightweight migration and restore selection-free.
- Treat stored Marquee metadata as an external boundary: exact-convert its
  integers, drop malformed or empty values, and delegate valid geometry
  clipping to the shared core.
- Keep Floating Selection transient. A save serializes the pre-lift pixel
  baseline and source Marquee without mutating the live Floating interaction.
