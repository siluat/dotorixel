## What to build

Expose the Reference Layer surface the Phase 5 reference track needs
through the UniFFI crate. **Expand only** — existing bindings and every
consumer stay untouched (the 256/263/267 pattern).

Scope is defined by what the reference slices consume:

- **Singleton add/replace**: wrap the core's reference-layer creation —
  source RGBA pixels + natural dimensions in, singleton semantics out
  (repeat imports replace, never duplicate; the layer sits fixed at the
  bottom of the stack). Core validation errors surface as thrown errors.
- **Placement**: a record for the placement value (position, scale,
  quarter-turn rotation), the placement write, and the fit-to-canvas
  computation. The core constructor's invariants (finite position,
  scale > 0, rotation 0..=3) reject invalid values at the boundary.
- **Reads for rendering and interaction**: per-layer reads the underlay
  render path and placement overlay consume — source pixels, natural
  dimensions, current placement, and the rotation-aware footprint (the
  min/max extent the navigation-bounds slice unions with the canvas).
- **Sampling**: the what-you-see pixel read (`try_get_pixel` semantics —
  topmost visible content at a coordinate, reference underlay included)
  that the eyedropper/loupe slice switches to.
- The existing metadata read already carries the layer kind tag; verify
  the reference kind crosses the boundary correctly now that it is
  reachable.

No new core logic; binding work plus regeneration. The persistence-snapshot
rework (today's snapshot read errors on a Reference Layer) belongs to the
persistence slice (282), not here.

## Acceptance criteria

- Swift binding tests (following the `DocumentBindingsTests` pattern)
  prove through the generated bindings:
  - importing twice yields one reference layer (replacement, not append),
    fixed bottom-most, with the second source's data;
  - pixel-layer reorder can never place a layer below the reference;
  - placement writes round-trip; invalid placement values throw;
  - fit-to-canvas produces the expected placement for representative
    canvas/source aspect combinations;
  - the footprint read reflects placement position/scale/rotation;
  - the sampling read returns reference content where no pixel-layer
    pixel covers it, and pixel-layer content where one does;
  - `composite()` and `composite_for_export()` are byte-identical with
    and without a visible reference (Pixel-only composite).
- `cargo test` passes; UniFFI regeneration produces Swift that compiles
  in the Xcode project.
- Existing bindings, shell code, and shell behavior are untouched.
