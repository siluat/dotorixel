## What to build

The Reference Layer arrives on the Apple shell: import an image and it
appears as the singleton tracing underlay beneath the artwork, with its
row in the Timeline panel.

- **Import**: an add-reference affordance in the Timeline panel header
  (web's placement) opens the native file picker (macOS open panel /
  iPadOS Files). Accepted formats and the size limit mirror the web's
  import pipeline; the image decodes to RGBA shell-side and enters the
  document through the 277 bindings with auto-fit placement. Re-importing
  replaces the existing reference (singleton), with placement reset to
  fit. Oversized or undecodable files surface an actionable message and
  leave the document untouched.
- **Underlay render**: the original source image draws beneath the pixel
  composite — outside the document's pixel buffers, per the web's
  underlay model — transformed by placement (position, scale,
  quarter-turn) and the viewport (zoom/pan), nearest-neighbor scaled.
  Visibility toggles live. Export composites and saved-work thumbnails
  remain Pixel-only (core guarantees it; verify at the shell).
- **Timeline row**: the reference row renders bottom-most with its kind
  icon, name, visibility toggle, and delete — and no reorder affordance
  (fixed position). Delete removes the underlay and the row; add/replace/
  delete are undoable document edits.
- **Auto-save stays healthy**: today's persistence snapshot read errors on
  a Reference Layer, which would make every auto-save of a
  reference-carrying document fail. Until the persistence slice (282)
  lands, the save path must keep working — persist the pixel layers and
  skip the reference at the snapshot boundary, loudly documented as a
  known gap (the reference is absent after relaunch, never a crash or an
  aborted save).

## Acceptance criteria

- Import from the Timeline header shows the image under the artwork at
  fit-to-canvas placement; drawing on pixel layers renders above it.
- A second import replaces the first (one row, new image, placement
  reset); delete removes it; both undoable.
- Visibility toggle hides/shows the underlay without touching pixel
  layers; PNG export bytes are identical with the reference visible and
  hidden.
- Invalid files (unsupported format, over the size limit, corrupt data)
  produce an actionable error and no document change.
- With a reference present, auto-save succeeds and relaunch restores the
  pixel layers (reference absence is the documented 282 gap).
- Tests cover the import decode/validation boundary, singleton
  replacement, underlay projection math (placement × viewport), row
  affordances, Pixel-only export, and the snapshot-skip save path.

### Key Decisions

- Kept file decoding and viewport rendering native to the Apple shell because both are platform-specific boundaries; the shared core remains authoritative for Reference identity, placement, history, and sampling geometry.
- Passed one production render projection into Metal so tests exercise the same placement × viewport contract the shader consumes.
- Preserved the issue-278 persistence boundary as an explicit Pixel-only projection: Reference imports never abort auto-save, while full Reference durability remains owned by issue 282.

### Notes

- Reference source, placement, and visibility are intentionally absent after relaunch until issue 282; Pixel Layers and saved-work thumbnails remain healthy and Pixel-only.
- Direct Reference editing, sampling, placement interaction, and Reference-aware navigation bounds remain in issues 279–281.
