## What to build

Web-parity Navigation Bounds: with a reference placed partly outside the
canvas, the user must be able to pan/zoom out far enough to see and grab
it — today's canvas-only clamp would strand it off-screen.

- Every viewport sink (pan, pinch/zoom, zoom-at-point, fit-to-viewport,
  and the reclamps after resize and rotate) clamps against the union of
  the canvas rect and the **active** reference's footprint, matching the
  web's rule: the union applies while the reference is active; with a
  Pixel Layer active the bounds are the canvas alone (the web computes the
  union shell-side over the core's rotation-aware footprint and clamp —
  same split here).
- Fit-to-viewport fits the union when the reference is active, so "fit"
  brings the whole tracing setup into view.
- Placement edits (280) and activation changes update the bounds live; a
  reference dragged further out extends them, deleting it or switching to
  a Pixel Layer shrinks them back with a smooth reclamp, never a jump
  through invalid state.

## Acceptance criteria

- With the reference active and extending past the canvas, panning reaches
  the reference's far edge; with a Pixel Layer active, the canvas-only
  clamp is exactly today's behavior.
- Fit-to-viewport with the reference active frames canvas + reference;
  with a Pixel Layer active it frames the canvas (unchanged).
- Moving/scaling the reference updates the reachable area immediately;
  deleting it or deactivating restores canvas bounds without leaving the
  viewport outside the new clamp.
- Tests cover the union math per sink, the active/inactive switch, the
  live update on placement change, and the shrink-reclamp.

### Key Decisions

- **Fit frames the canvas, not the union** — deviating from this issue's original acceptance criterion by user decision: the web's Fit targets the canvas rect and only *clamps* against the union, and Apple now matches that exactly rather than introducing a cross-shell divergence. When containment demands it the clamped fit still shifts pan so the whole union stays visible (same as the web's `zoomFit → apply` path).
- **Union computed shell-side** (per the issue): the core owns the rotation-aware footprint and the document-bounds clamp; each shell unions canvas ∪ footprint itself — the same split the web chose in issue 160.
- **Footprint source = `referencePlacementTarget?.footprint`**: active + visible Reference only, with the in-flight placement draft substituted — bounds extend live during a drag and shrink back on cancel/commit through explicit `reclampViewport` calls (Apple's mutations are imperative, unlike the web's journal-driven reclamp).

### Notes

- The canvas-only `clampPan` binding now has no callers in the Apple shell (production or tests) — a binding-surface shrink candidate for a later review pass (the web kept its counterpart because tests still use it).
- The rejected-commit path after a mid-gesture Reference replacement needs no extra reclamp: `previewedPlacement`'s `targetKey == sourceKey` guard already stops the stale draft from feeding the footprint, and `setReferenceLayer`'s reclamp handles the shrink.
- A blank symmetric document's rotation resolves to a no-op Edit and skips the rotation reclamp entirely — the rotation test paints one pixel to keep the path exercised.
