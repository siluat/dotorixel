## What to build

Web-parity Navigation Bounds: with a reference placed partly outside the
canvas, the user must be able to pan/zoom out far enough to see and grab
it — today's canvas-only clamp would strand it off-screen.

- Every viewport sink (pan, pinch/zoom, zoom-at-point, fit-to-viewport,
  and the reclamps after resize and rotate) clamps against the union of
  the canvas rect and the **active** reference's footprint, matching the
  web's rule: the union applies while the reference is active; with a
  Pixel Layer active the bounds are the canvas alone (the web computes the
  union shell-side over the core's rotation-aware footprint and clamp —
  same split here).
- Fit-to-viewport fits the union when the reference is active, so "fit"
  brings the whole tracing setup into view.
- Placement edits (280) and activation changes update the bounds live; a
  reference dragged further out extends them, deleting it or switching to
  a Pixel Layer shrinks them back with a smooth reclamp, never a jump
  through invalid state.

## Acceptance criteria

- With the reference active and extending past the canvas, panning reaches
  the reference's far edge; with a Pixel Layer active, the canvas-only
  clamp is exactly today's behavior.
- Fit-to-viewport with the reference active frames canvas + reference;
  with a Pixel Layer active it frames the canvas (unchanged).
- Moving/scaling the reference updates the reachable area immediately;
  deleting it or deactivating restores canvas bounds without leaving the
  viewport outside the new clamp.
- Tests cover the union math per sink, the active/inactive switch, the
  live update on placement change, and the shrink-reclamp.
