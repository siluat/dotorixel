## What to build

The Apple analog of the web's v4 migration (issues 114/115/126): the
Reference Layer joins the SwiftData session schema, closing the
documented 278 gap where a reference vanishes on relaunch.

- **Snapshot reads**: rework the persistence snapshot path so a
  reference-carrying document serializes instead of erroring — the
  reference contributes its source pixels (stored compressed, e.g.
  PNG-encoded, matching the web's blob approach), natural dimensions,
  placement, visibility, and name; pixel layers persist exactly as today.
  This is the deferred binding rework 277 left out — expand-only where
  possible, and the 278 skip-at-the-boundary workaround comes out.
- **Schema**: the per-document record gains the optional reference fields
  (absent = no reference). Existing stored sessions restore unchanged.
- **Restore**: hydration rebuilds the reference through the 277 bindings —
  underlay, Timeline row, placement, and visibility all return exactly as
  saved. Hydration normalizes to at most one bottom-most reference (web's
  v4 normalization); a corrupt blob or invalid placement drops the
  reference at the boundary rather than discarding the session or
  crashing.
- Reference mutations (import, replace, delete, placement, visibility)
  mark the document dirty so the debounced auto-save picks them up;
  saved-work browser thumbnails stay Pixel-only.

## Acceptance criteria

- Import a reference, position and scale it, relaunch: the underlay, its
  row, placement, and visibility are exactly as left. Delete it, relaunch:
  gone.
- A pre-existing stored session (no reference fields) restores unchanged;
  a corrupt reference blob or invalid placement yields the document
  without its reference — never a crash, never a lost session.
- Every reference mutation triggers the auto-save path; the saved-work
  browser thumbnail for a reference-carrying document shows pixel art
  only.
- Round-trip fidelity: the restored source buffer is pixel-identical to
  the imported image (compression is lossless).
- Binding tests cover the reference-aware snapshot reads/hydration;
  persistence tests (in-memory store) cover the round-trip, absent
  fields, normalization, and corruption fallbacks.

### Key Decisions

- **Single hydration authority**: `fromLayers(reference:)` mirrors the wasm
  builder; the core's `normalize_reference_underlay` performs the
  bottom-most-singleton normalization. No shell-side rebuild sequence.
- **PNG codec in core**, paired with the existing encoder: the lossless
  round-trip has one implementation, and ImageIO re-decoding (premultiplied
  alpha, rounding loss) is structurally excluded from the persistence path.
- **Corruption blast radius**: a corrupt blob, invalid placement, invalid
  id, or an id colliding with a Pixel Layer drops the reference at the
  persistence boundary; after a drop, an active pointer left outside the
  Pixel stack remaps to the topmost Pixel Layer. Never a lost session.
  (Collision drop + decode allocation bound added in the PR #370 review
  pass — greptile/cubic findings.)
- **`rotation` is stored** (web schema parity; future rotate polish) and
  restored exactly, though nothing on this shell produces a non-zero value yet.
- **Vocabulary alignment** (guide-compliance pass): the snapshot record uses
  `naturalWidth`/`naturalHeight` (matching core, underlay, and the web
  snapshot); the stored blob field is `sourcePng` (web `sourceBlob` parity).

### Notes

- `decode_rgba_png` takes a caller-owned `max_pixel_bytes` bound (the Apple
  binding passes the import boundary's 64 MiB decoded-RGBA cap) so a corrupt
  header's declared dimensions cost an error, never an allocation abort.
- An encode failure at save time (core-guaranteed not to occur) would drop
  the reference from that record rather than abort the auto-save.
- Two tests pinning the 278 skip contract were rewritten to the new contract
  (`WorkspaceSnapshotTests`, `AutoSaveTests`); they are replacements, not
  lost coverage.
