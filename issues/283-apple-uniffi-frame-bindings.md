## What to build

Expose the frame-axis surface the Phase 6 animation track needs through
the UniFFI crate. **Expand only** — existing bindings and every consumer
stay untouched (the 256/263/267/277 pattern).

Scope is defined by what the animation slices consume:

- **Frame metadata reads**: every frame's identity and display duration
  in axis order (the web binding's `frames_metadata` shape: id +
  `duration_ms`), the active frame id, and the frame count. Frames carry
  no name — the shell displays 1-based ordinals.
- **Frame operations**: add (insert an empty frame after the active one
  and activate it), duplicate (clone every Pixel Layer's active-frame
  Cel and activate the copy), remove (reject the last frame; relocate
  the active pointer to an adjacent frame), reorder (active pointer
  preserved by id), and set-active-frame. The core cannot mint UUIDs, so
  add/duplicate take caller-supplied new-frame ids, exactly as
  `add_layer` does. Core `FrameError` variants surface as thrown errors.
- **Per-frame duration write**: set a frame's display duration. The core
  trusts the value, so this binding owns the valid range and clamps to
  it — the same 1–60 000 ms bounds the web binding owns — and exposes
  the bounds as constants so the shell UI and the binding agree.
- **Per-frame composite**: the read-only, frame-addressed sibling of
  `composite()` (`composite_at`) that Playback, Onion Skin, and the
  export encoders all read. The binding confirms the frame exists before
  delegating (the wasm-boundary precedent); the Active Frame is neither
  consulted nor moved.

No new core logic; binding work plus regeneration. The export encoders
(SVG/GIF/spritesheet) belong to the export track's binding slice (293),
and the frames-aware hydration path belongs to the persistence slice
(292), not here.

## Acceptance criteria

- Swift binding tests (following the `DocumentBindingsTests` pattern)
  prove through the generated bindings:
  - a new document reports exactly one frame with the default duration;
  - add inserts after the active frame, seeds transparent Cels for every
    Pixel Layer, and activates the new frame;
  - duplicate reproduces the source frame's composite on the new frame;
  - removing the last remaining frame throws; removing the active frame
    relocates the active pointer to an adjacent frame;
  - reorder rearranges the axis and preserves the active pointer by id;
  - set-frame-duration round-trips, and out-of-range values clamp to the
    binding-owned bounds;
  - `composite_at` returns the requested frame's composite (distinct
    from the active frame's when their Cels differ) without moving the
    active frame, and throws for an unknown frame id;
  - drawing writes only the active layer's active-frame Cel — other
    frames' composites are unchanged.
- Whole-document snapshot undo/redo restores frame structure and Cel
  pixels across a frame operation (history works unchanged on the
  expanded surface).
- `cargo test` passes; UniFFI regeneration produces Swift that compiles
  in the Xcode project.
- Existing bindings, shell code, and shell behavior are untouched.
