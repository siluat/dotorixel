## What to build

Drag-to-reorder on the frame ruler, mirroring how the layer rows reorder
(the 259 → 260 sequencing precedent — structure first, drag second):

- **Drag a frame header horizontally** to move the frame to a new
  position on the axis; neighbors shift out of the way with the same
  drag-feedback treatment the layer rows use.
- The **active pointer is preserved by id** — the frame the user was
  editing stays active wherever it lands.
- The reorder is **undoable** through the whole-document snapshot
  history.
- Reuse/extend the extracted layer reorder-drag interaction rather than
  building a parallel implementation; adopt the same self-heal guards
  the layer drag gained (structure mutation mid-drag cancels the drag;
  panel collapse cancels it). The system-level interrupted-drag residual
  (app backgrounded mid-drag) remains tracked by the existing backlog
  item covering all drag surfaces — do not solve it here.

## Acceptance criteria

- Dragging a frame header reorders the axis; the composite shown for
  each ordinal follows the frame's content.
- The active frame stays active across a reorder, including when other
  frames move past it.
- A structural change mid-drag (e.g. a frame removed by undo) cancels
  the drag cleanly with no stuck preview offsets.
- Undo restores the previous order; redo reapplies the move.
- Snapshot baselines updated where the drag affordance changes chrome.
