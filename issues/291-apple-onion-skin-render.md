## What to build

Put the 290 ghost projection on screen and give it its control (web
PRD 217's render contract, adapted to the Metal render path):

- **Ghost rendering**: ghosts draw above the Reference underlay and
  below the Active Frame's artwork — farthest first, nearest last. The
  previous frame renders with a warm tint, the next with a cool tint;
  both clearly dimmer than committed artwork; ghost transparency is
  preserved (checkerboard and reference show through). Whether the tint
  is applied in the Metal pass or as a CPU pre-composite is an
  implementation decision — the contract is the layered result. Tint and
  alpha values derive from existing design tokens (web values as
  reference).
- **Ghosts are a pure view aid**: they never appear in Playback,
  exports, or saved-work thumbnails, and drawing tools ignore them.
- **Toggle in the transport strip**, beside Loop: pressed-state
  semantics, disabled for a single-frame document, per-tab.
- Suppression during Playback and restoration on stop arrive from the
  290 projection — verify the visible behavior end to end here.

## Acceptance criteria

- With the toggle on, the canvas shows the previous frame's ghost
  (warm), the next frame's ghost (cool), and the Active Frame's art on
  top; on the first/last frame only the existing side shows.
- Ghosts update immediately after editing a neighbor, undo/redo, and
  frame switches.
- Ghosts disappear while playing and return when stopped; PNG export of
  the active frame is byte-identical with the toggle on and off.
- Toggling pushes no history entry and never marks the document dirty.
- Toggle reflects its state visually and to accessibility; disabled with
  one frame; touch target ≥ 44 pt; labels in the String Catalog
  (en/ko/ja); snapshot baselines updated.
