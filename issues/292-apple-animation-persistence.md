## What to build

Extend the SwiftData session schema so a multi-frame animation survives
relaunch — the Apple sibling of the web's v5→v6/v7 migrations, using the
optional-field pattern the reference persistence slice (282) established:

- **Schema extension**: the document record gains the frame axis —
  ordered frames (id + duration ms) and the active frame id — and each
  stored Pixel Layer's single pixel buffer generalizes to one Cel per
  frame. New fields are optional/defaulted so **old stores restore
  unchanged**: a record without frame data hydrates as a one-frame
  document whose single Cel is the stored pixel buffer, with the default
  duration — no pixel loss, no migration pass.
- **Hydration**: extend the single `fromLayers` hydration path (the 282
  decision) so restore rebuilds the full Layer × Frame grid and the
  active frame in one validated step. This is the frames-aware binding
  extension deferred from 283. Invalid animation data (unknown active
  frame id, cel/frame mismatch) degrades the way 282 degrades a corrupt
  reference: the document falls back to a consistent state rather than
  dropping the session.
- **Save**: auto-save and explicit save persist every Cel of every Pixel
  Layer, frame order, per-frame durations, and the active frame id.
- **Onion skin toggle** joins the per-tab stored viewport state beside
  the grid flag (optional field, absent reads as off), matching the
  web's viewport-record treatment. Playback state never persists — a
  document always opens stopped.

## Acceptance criteria

- Round-trip: a multi-frame document with distinct per-frame content,
  per-frame durations, and a non-first active frame saves and restores
  byte-identically (per-frame composite parity), with the active frame
  and frame order preserved.
- A store written before this slice restores as a one-frame document
  with the original pixels intact.
- Inconsistent stored animation data restores to a consistent document
  without discarding the session.
- The onion skin toggle survives relaunch per tab; playback state does
  not.
- Saved-work browser reopen flows work for multi-frame documents
  (thumbnail shows the active frame's composite, ghosts never included).

### Key Decisions

- **One validated hydration step in core** (`Document::from_grid`), not the
  web's post-build replay (`hydrateFrames`) — extends the 282 "single
  hydration authority" decision. `from_layers` delegates, so wasm and every
  existing caller are untouched.
- **Degrade policy** (the 282 reference-drop precedent): a grid hydration
  would reject — missing/extra/duplicate cels, unparseable frame ids, a
  non-round-trippable duration — drops the frame axis and restores a
  one-frame document from each layer's active-frame `pixels`; an unknown
  active frame pointer alone remaps to the first frame with the axis kept.
  Never a lost session.
- **`pixels` stays the active frame's cel** (one buffer of deliberate
  storage duplication): it preserves the pre-292 field meaning and is the
  degrade fallback's data source. `cels` is authoritative when present.
- **`frames` / `activeFrameId` cross as two optional params**, not a
  combined record — web `HydrationSource` parity (`frames?` /
  `activeFrameId?`) and core-signature symmetry won over making the
  supplied-together invariant structural; the inconsistent call errors at
  the boundary, test-pinned.
- **Onion-skin toggle marks the workspace**, not the document — the flag
  lives in the workspace record's viewports, and naming the document would
  rewrite its layers and stamp `updatedAt` (the PR #351 reasoning).
  `toggleGrid`'s document mark is the same mismatch; filed in the review
  backlog rather than widened here.
- 290's "toggle never dirty" contract test was **rewritten to the 292
  contract** (replacement, not lost coverage — the 282 precedent).

### Notes

- `isDocumentBlank` now scans every cel, so paint on an inactive frame
  blocks the tab-close flow from silently discarding it — an adjacent-scope
  fix the multi-frame schema made necessary, test-pinned.
- The animation screen's `width * height * 4` uses overflow-checked
  multiplication, honoring the `CorruptRecord` no-trap principle for
  store-sourced numbers.
- `CelGridMismatch` replaced `MissingInitialFrameCel` /
  `MultiFramePixelLayer` (no external users; no test pinned the old wasm
  message strings).
- The saved-document reopen path resets the onion skin with the rest of the
  viewport (the CONTEXT.md Onion Skin contract), pinned by the reopen test.
