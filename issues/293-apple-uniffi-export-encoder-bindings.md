## What to build

Expose the core's remaining export encoders through the UniFFI crate.
**Expand only** — existing bindings (including the PNG export path) and
every consumer stay untouched:

- **SVG**: the document's export composite encoded as an SVG string —
  one `<rect>` per non-transparent pixel, `viewBox`-only root with
  `crispEdges`, mirroring what the web binding exposes.
- **Animated GIF**: the core `GifExport` contract — frames in axis order
  with per-frame delays quantized to centiseconds, infinite looping,
  binary transparency at the alpha-128 threshold, Reference Layers and
  hidden layers excluded, the active frame untouched.
- **Spritesheet PNG**: the core `SpritesheetExport` contract — a
  horizontal strip of every frame's composite, tile width × frame count,
  no padding, same exclusions, active frame untouched.
- Core `ExportError` variants (including `SheetTooLarge` and
  `GifEncode`) surface as thrown errors the shell can present.

No new core logic; binding work plus regeneration.

## Acceptance criteria

- Swift binding tests (following the `DocumentBindingsTests` pattern)
  prove through the generated bindings:
  - SVG output contains the expected rects for a known pixel pattern and
    omits transparent pixels;
  - GIF bytes for a two-frame document decode as two frames whose delays
    reflect the frames' durations (centisecond quantization);
  - the spritesheet's dimensions are canvas width × frame count by
    canvas height, and each tile matches its frame's composite;
  - a hidden layer and a visible Reference Layer appear in none of the
    three outputs;
  - encoding leaves the active frame and document state untouched.
- `cargo test` passes; UniFFI regeneration produces Swift that compiles
  in the Xcode project.
- Existing bindings, shell code, and shell behavior are untouched.

### Key Decisions

- **SVG exposed at document level** (`encode_export_svg`, following the
  `encode_export_png` precedent), not the web's canvas-level
  `encode_svg` — confirmed with the user. The issue's "document's
  export composite" wording wins, and one binding call folds
  composite → canvas → SVG so the shell cannot misassemble it. Web
  parity holds semantically: the web shell performs the identical
  composition in `TabState.exportableSnapshot()`.
- **GIF delays asserted via `kCGImagePropertyGIFUnclampedDelayTime`** —
  the raw on-wire centisecond field, immune to the clamped substitute
  ImageIO reports for tiny delays.
- **Error docs only where an error path is reachable**: `encode_gif`
  (`GifEncode`) and `encode_spritesheet_png` (`SheetTooLarge`,
  `PngEncode`) document their conditions; `encode_export_svg` has no
  reachable failure beyond its signature, so none is stated.

### Notes

- The three methods surface in Swift as `throws -> Data` /
