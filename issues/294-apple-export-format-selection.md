## What to build

Grow the TopBar's single PNG export button into a format-selecting
export surface (the web's export popover as reference, delivered with
SwiftUI-native controls — a menu or equivalent platform idiom), and ship
SVG as the first new format:

- **Format selection**: the export affordance offers PNG and SVG now,
  with room for the spritesheet (295) and GIF (296) entries to slot in
  without reshaping the surface.
- **PNG behavior is unchanged**: single image of the frame the user is
  viewing, through the existing file-export flow.
- **SVG export**: the 293 SVG encoder wired through the file exporter
  with the correct content type and a filename consistent with the
  existing PNG naming.
- Export failures surface through the existing export-error presentation
  with actionable messages.
- Exports never contain onion-skin ghosts or the Reference underlay
  (encoder contract — verify at this surface).

## Acceptance criteria

- The export control offers PNG and SVG; each produces a well-formed
  file through the platform file-export flow.
- The exported SVG opens in a browser and matches the canvas content
  (spot-check via known pixel pattern in tests; visual check in
  verification).
- PNG export behavior and its tests are unchanged.
- Encoder errors present the existing alert path with the core's
  actionable message.
- Touch targets ≥ 44 pt; new labels in the String Catalog (en/ko/ja);
  snapshot baselines updated.

### Key Decisions

- **Registry as a Swift enum**, mirroring the web's declarative format list — the
  export surface (menu, exporter, filename) reads the registry, so 295/296 add
  cases without reshaping the UI.
- **PNG contract untouched**: `makePngExportDocument()` / `defaultExportFilename`
  remain as delegating wrappers so `PngExportTests` and `RenderPathTests` stay
  byte-for-byte unchanged (acceptance criterion).
- **No new String Catalog entries**: the "new labels in the String Catalog
  (en/ko/ja)" acceptance criterion is satisfied vacuously — the surface
  introduces zero new translatable strings. The only new visible labels are the
  format acronyms (PNG/SVG), rendered verbatim exactly like the web registry's
  untranslated labels; existing "Export" / "Export Failed" entries are reused.
- **No filename input field**: the platform save flow (macOS save panel /
  iPadOS Files picker) already edits the filename, so the web popover's input
  has no Apple counterpart.
