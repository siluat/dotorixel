## What to build

Add the animated-GIF format to the 294 export surface:

- **Animated GIF**: every frame's composite in axis order (the 293
  encoder), each frame held for its authored duration (centisecond
  quantization per the core contract), looping forever, exported through
  the platform file-export flow with the GIF content type.
- What plays in the editor is what exports: layer visibility applied,
  Reference Layers excluded, binary transparency at the core's
  threshold.
- GIF encoding failures surface through the export-error presentation.

## Acceptance criteria

- Exporting a multi-frame document yields a GIF that animates with the
  authored per-frame timing (a retimed frame visibly holds longer) and
  loops.
- A single-frame document exports a valid single-frame GIF.
- A hidden layer and a visible Reference Layer appear in no exported
  frame; transparent regions never ghost earlier frames.
- The active frame and document state are untouched by an export.
- New labels in the String Catalog (en/ko/ja).

### Key Decisions

- "GIF" stays an untranslated acronym like the web registry's label
  (`() => 'GIF'`), so the "new String Catalog labels" acceptance criterion
  turned out vacuous — no localizable strings were added (unlike 295's
  "Spritesheet").
- Hidden/Reference-layer exclusion, ghosting prevention (disposal),
  centisecond quantization, and encode purity were not re-tested at the
  shell seam — the core (`export.rs`) and the 293 FFI binding tests
  already cover them.
